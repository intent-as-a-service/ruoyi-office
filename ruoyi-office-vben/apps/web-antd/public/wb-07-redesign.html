1对象与金额要成为一等公民产品经理

症状 队列项写着「第 1 期回款已逾期 23 天」——客户名根本没出现，金额被压在第二行 11px 灰字里。 18 条信号其实是 16 个对象，其中「宏图建筑设计院」同时挂着"逾期 1.2 万"和"待跟进"，却分成两条。
根因 规则模板没写对象名：10-crm-receivable-plan-overdue.yaml:19 的 title: "第 {{row.period}} 期回款已逾期 {{row.overdueDays}} 天"。 而数据集本身也没有这一列 —— CrmIntentFactProvider.java:116-119 只声明了 id / period / price / returnTime / overdueDays / customerId / contractId。 对照 40-crm-customer-follow.yaml:19 的 title: "客户「{{row.name}}」待跟进"：同一个系统里，有的规则带对象名、有的不带。
改法 ① 数据集补一列 customerName（批量查一次客户名）； ② 模板补对象名：「客户「X」第 N 期回款已逾期 M 天」； ③ 建议结构上补 objectType / objectId / objectLabel，让 UI 把它渲染成主语而不是解析字符串； ④ 按对象聚合一次 —— 18 条 → 16 件，同客户的钱与关系合成一张卡。

2左栏的空间分配反了UI 设计师

症状 左栏 620px 高里，空的配置区占了约 60%（1 个时间窗 + 5 个空槽位 + 3 处重复的"加实体"入口 + 5 条"「X」槽空着 ⇒ N 条能力收起"），而"今天要做什么"被挤到只剩 3 行、第 4 行就被截断。
判断 空间给谁，就是在告诉用户"什么重要"。现在给的是配置，而用户要的是活。 "加实体"入口重复了三次（标题行 / 每个空槽位 / 底部），"几条能力收起"是实施者语言，销售不关心。
改法 ① 上下文默认收成一行 chip（有值才显示 + 一个 ＋），点开才展开成面板 —— 这正是设计稿 §4 原本写的"收起 56px"； ② 三处"加实体"合并成一个 ＋； ③ "几条能力收起"收成一句、且只在展开态出现。

3右栏是"日志墙"，不是"执行流"业务专家

症状 整个右栏是 6 条一模一样的「今日跟进优先级」，每条占一整行；其中 4 条是 44~83 毫秒的失败（配置模型密钥之前留下的脏记录），和 2 条成功记录混在一起、无从区分。 顶部还留着一大块空态「从左边挑一件事」，与下面的内容并存。
判断 执行流的价值是"我最近在反复跑什么、上一次结果是什么"。 逐条平铺同一件事，等于把一个问题重复六遍；而失败记录不清，用户会怀疑系统是不是坏了。
改法 ① 同一意图的连续 Run 折叠成一组：「跑了 6 次 · 最近 23 秒前」； ② 失败单独成组，给「清理」，并标注是哪段时间的记录； ③ 有 Run 时不再渲染空态； ④ 组内只展开最新一条，其余折成一行。

一句话归纳：改版前的首屏把 90% 的屏幕给了"配置"和"历史"， 只把 10% 给了"今天的活"——而"今天的活"里最重要的两样东西（是谁、多少钱）都藏在第二行的小灰字里。 这次的三条改动就是把比例调回来：配置降为一行、历史收成一组、把对象和金额提到一级信息。
